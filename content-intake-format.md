# Case Study Content Intake Format

Use this format when sharing raw case-study content. Keep it simple. Bullets are fine. Rough notes are fine. I will convert the raw material into the portfolio schema later.

Important rule: final portfolio content should be generated strictly from the sources you provide. If something is missing, it should be marked as a gap or question, not guessed.

## 1. Basic Details

```text
Working title:
Company: CommerceIQ / Leap / Other
Timeframe:
Your role:
Team/collaborators:
Confidentiality level: public / sanitized / confidential summary
Can we mention company name publicly? yes/no
```

## 2. One-Line Summary

```text
In one sentence, what was this project about?
```

## 3. Problem

```text
What was the user/customer/business problem?
Who was feeling the pain?
Why did it matter?
```

## 4. Users And Stakeholders

```text
Primary users:
Internal stakeholders:
External customers/partners:
Decision makers:
```

## 5. Business Goal

```text
What business outcome were you trying to drive?
Revenue, adoption, efficiency, retention, conversion, cost reduction, risk reduction, customer satisfaction, etc.
```

## 6. Constraints

```text
What made the problem hard?
Examples: timeline, data quality, engineering capacity, customer commitments, privacy, integrations, stakeholder alignment, go-to-market dependencies.
```

## 7. Your Product Work

```text
What did you personally own?
What decisions did you drive?
What tradeoffs did you make?
What alternatives did you consider?
```

## 8. Technical / System Context

```text
What systems, data flows, APIs, platforms, integrations, analytics, ML/AI, or technical constraints mattered?
What did you need to understand technically to make good product decisions?
```

## 9. Outcome / Impact

```text
What changed because of the work?
Metrics:
Qualitative outcomes:
Customer/user feedback:
Business impact:
Operational impact:
If exact numbers are confidential, provide sanitized or directional language.
```

## 10. Proof Artifacts

```text
Links:
Screenshots:
Docs/PRDs:
Launch notes:
Dashboards:
Customer quotes:
GitHub/demo, if relevant:
What can be public?
What needs to be sanitized?
```

## 11. Lessons

```text
What did you learn?
What would you do differently?
What product principle does this project show?
```
